# Durable assessment images during generation

Generation handles images only in question stimuli at `pg[]`, `isian.data[]`, and `uraian[]`, and only the corresponding question's `gambar` property. It does not recursively fetch arbitrary object URLs. Raster inputs are ingested through the assessment asset helper, which enforces trusted HTTPS origins, no redirects, image validation, and per-asset/owner limits. Provider URLs are transient in-memory values; they are removed before package content is written, and controlled warnings contain a question number and reason rather than a URL.

Each package may reference at most eight unique raster assets totaling 4 MiB. Existing asset IDs are checked against the authenticated owner's persisted asset records before use. Count/byte-limit and ingest failures keep the question text unchanged, replace the unavailable source with `imageUnavailable` plus a controlled reason, and return additive `_persistence.imageWarnings`. The package helper owns package creation, canonical content, and the atomic package/asset association write; generation does not duplicate its SQL. A failed package write returns `_persistence: { packageId: null, revision: null, saveStatus: "failed", imageWarnings }`. Telemetry is best effort and independent.

Supported diagrams are rebuilt from structured `visual_stimulus` parameters by the application's existing visual renderer. Renderer output is trusted and requires no image-asset request or raster quota. Model/client-supplied SVG strings, SVG data URIs, scripts, and external SVG references are never trusted or persisted; they become an unavailable stimulus warning. No additional image-generation request or provider retry is made.

`POST /api/kisi/regenerate-batch` uses the same image normalization before returning replacements, but does not create a package. Raster assets are owned by the authenticated user; the caller's subsequent owner-authorized CAS package save is responsible for attaching them. A failed/expired signed URL cannot be recovered by this pipeline. Recovery requires original image bytes from an original upload or an embedded DOCX/PDF; do not treat a regenerated image as restoration of the original.

Focused regression coverage uses mocked provider fetches and migration-backed in-memory SQLite. It does not use provider credentials, contact a real image provider, apply a production migration, or deploy code.
