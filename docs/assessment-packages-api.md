# Assessment package persistence API

All routes require an authenticated session or bearer token.

* `POST /api/banksoal` creates a private package. Optional `clientDocumentId` (UUID) makes retries idempotent per owner. Existing package metadata and `content` fields remain accepted. Response adds `packageId`, `revision: 1`, and `saveStatus: "saved"`.
* `GET /api/banksoal/:id` returns the existing package detail shape with parsed image references rewritten to `/api/banksoal/:id/assets/:assetId` and additive `_persistence: { packageId, revision, saveStatus: "saved"|"failed", imageWarnings: [] }`.
* `PUT /api/banksoal/:id` is owner-only. Send `{baseRevision, content, ...optional package metadata}`. The request stream is capped at 1 MiB; at most eight owned raster asset references totaling 4 MiB are allowed. A successful content change increments revision and returns `{packageId, revision, saveStatus:"saved"}`. It preserves current sharing intent and keeps public submissions pending after edits; use the explicit share endpoint to alter that intent. Stale revisions return HTTP 409; clients must retain local work.
* `GET /api/banksoal/:id/assets/:assetId` serves bytes only while the asset is currently associated with the package and the requester can currently access that package. It returns the stored image MIME with `nosniff` and `private, no-store`.
* `POST /api/banksoal/:id/copy` accepts `{clientDocumentId?}`. It copies only a currently owner-accessible or public source into a new private package, cloning currently associated raster bytes under recipient quotas and rewriting `assetId`s. Response is `{id, packageId, revision, saveStatus:"saved", imageWarnings, content, is_public:false, moderation_status:"private"}`. A matching retry returns the recipient's existing copy; reusing its ID for a different source/snapshot returns 409. Missing/unassociated legacy raster references remain explicit unavailable markers; no provider fetch is attempted by copy.
* `POST /api/banksoal/:id/recover-images` is owner-only and accepts `{baseRevision}`. It reads legacy URL aliases only from persisted question-image objects, attempts approved-host or inline-raster ingestion (no AI generation), and commits rewritten content/associations through the same CAS path as `PUT`. It preflights the eight-reference/4 MiB package budget and owner quota before any fetch; repeated identical URLs are fetched once and share one resulting asset. Exceeding a predictable budget rejects before fetching or writing assets. Response is `{packageId, revision, saveStatus:"saved", content, imageWarnings}`. If no recoverable URL is retained, it returns an explicit upload-original warning without changing revision. Expired, untrusted, oversized, or invalid images become unavailable markers and warnings. A CAS conflict after ingestion returns 409 and may leave an unassociated recipient-owned asset for ordinary quota cleanup; image/source URLs are not logged or returned.
* Moderation queue rows include `revision` and `content_hash`. Moderation requests must send a positive integer `{expectedRevision}` matching the queued revision; missing revisions are rejected and stale queue actions return 409.

Image writes canonicalize each question's image as an owned `assetId` with a server-derived package URL, a validated self-contained SVG, or an explicit unavailable marker with a bounded reason and safe text attribution. Image URL/data/source aliases are removed; an asset ID never makes accompanying SVG or source aliases authoritative. SVG is parsed as XML and rebuilt from an allowlisted tag/attribute/value set; active elements, custom entities, event attributes, CSS/external references, and external links are rejected. Validated application renderer specifications are rebuilt using the local renderer. This is a storage-boundary guarantee, not a claim that arbitrary downstream SVG consumers are safe.

The package helper preserves its existing unfenced call and adds an optional generation fence: `createOwnedAssessmentPackage(db, { ownerId, clientDocumentId?, content, metadata, generationFence? })`. `generationFence` is `AssessmentGenerationFence` from `src/lib/assessment-generation-requests.ts`: `{ownerId, clientDocumentId, runToken, jobId?}`; its owner/document identity must exactly match the helper arguments. The result contract is unchanged: `{packageId, revision, saveStatus:'saved', contentHash, content, visibility}`. A valid fence authorizes one conditional package insert, or an exact-content/hash/revision/asset-association token update for an existing stable package. Package associations, ledger completion (`package_id` identifies that token-latched package, `result_json` is literal `null`), write receipt, and identity selection share one D1 batch. The receipt and returned row are selected inside that batch. A fence that cannot latch or settle returns typed `generation_fenced_conflict`, mapped to HTTP 409; it never returns an unfenced owner/document winner. If an optional SSE job ID is present, its running lease is checked at the latch once, not rechecked mid-batch. A cancellation after batch completion is a no-op against the completed ledger row.

Generation response shapes remain unchanged apart from additive `_persistence`. Successful saved packages identify their persisted package/revision. `imageWarnings` identify required stimuli that could not be made durable. Generation telemetry failure does not prevent package persistence. SSE emits the same `_persistence` object in the final `done.data` payload.
