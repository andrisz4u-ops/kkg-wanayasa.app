# Certificate issuance lane (Stage 2)

Migration `0034_atomic_certificate_issuance.sql` creates the required singleton global sequence. Apply the migration before serving reflection or signing requests; if its row is absent, issuance fails with an explicit configuration error rather than silently restarting numbering.

The sequence spans all activities because visible certificate numbers do not include an activity identifier. Migration 0034 seeds the singleton high-water mark from historical number components immediately before `/KKG-G3.WNY/`, across all statuses (including revoked rows), before any later cascades can remove their owners or activities. Before allocating, the issuer also scans historical numbers defensively, accepts only a complete `prefix/number/KKG-G3.WNY/month/year` number, ignores `DRAFT-*`, reports other malformed non-draft values to the server log, and raises the high-water mark. The increment, conditional draft upgrade, and winner read execute in one D1 batch. Retries retain the persisted number and token. Existing real numbers are not renumbered; `revoked` and unknown statuses cannot be changed into issued certificates. Numbers have at least three digits and are never truncated.

Issuance requires a valid activity date, current persisted attendance `hadir`, three nonblank trimmed reflection fields, and both persisted signature timestamps. Reflection writes use a conditional UPSERT keyed by `(kegiatan_id, user_id)`: attendance is checked in the write, the conflict branch changes only reflection fields on `draft`/`terbit` rows, and its response uses the persisted winner's token and issuance state. This avoids the concurrent first-submit UNIQUE race without overwriting certificate number/token, status, tenant data, or other stored fields. Status, portfolio, detail validity, public verification, and download readiness use the same issuance requirements; legacy incomplete numbers remain stored but are not represented as ready/verified.

Malformed legacy values are intentionally not repaired by this migration or issuer. Review logged values operationally; do not change historical numbers as part of this lane. The migration is additive and has not been applied to production by this change.
